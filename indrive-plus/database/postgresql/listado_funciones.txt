# Funcionalidad de la Base de Datos PostgreSQL — inDrive+

La base de datos PostgreSQL del proyecto inDrive+ tiene como objetivo gestionar la información transaccional principal del sistema de transporte inteligente. Su diseño sigue una arquitectura robusta y escalable orientada a microservicios, permitiendo manejar usuarios, autenticación, vehículos y viajes de manera segura y eficiente.

## Funcionalidades principales

### 1. Gestión de usuarios

La tabla `users` permite registrar y administrar los distintos tipos de usuarios del sistema:

* Pasajeros
* Conductores
* Administradores

Además, almacena información importante como:

* nombre
* correo electrónico
* contraseña encriptada
* teléfono
* estado de cuenta activa/inactiva

Esto permite implementar:

* registro de usuarios
* inicio de sesión
* control de acceso por roles
* validación de cuentas activas

---

### 2. Sistema de autenticación y tokens JWT

La tabla `tokens` permite gestionar la autenticación segura mediante JWT (JSON Web Token).

Sus funcionalidades incluyen:

* almacenamiento de tokens de acceso
* manejo de refresh tokens
* control de expiración de sesiones
* cierre de sesión seguro
* revocación de tokens comprometidos

Esto mejora la seguridad y permite un control más profesional de sesiones activas dentro del sistema.

---

### 3. Gestión de vehículos

La tabla `vehicles` administra la información de los vehículos asociados a los conductores.

Permite almacenar:

* marca
* modelo
* placa
* color
* año del vehículo

Además, garantiza que:

* un conductor tenga un único vehículo registrado
* no existan placas duplicadas
* los datos del vehículo sean válidos

---

### 4. Gestión de viajes

La tabla `trips` representa el núcleo operacional del sistema.

Permite gestionar:

* solicitud de viajes
* asignación de conductores
* inicio y finalización de trayectos
* cancelaciones
* seguimiento de estados del viaje

También almacena información importante como:

* origen y destino
* distancia recorrida
* precio base
* precio mínimo
* precio máximo
* precio final calculado

Esto permite integrar posteriormente el motor tarifario inteligente del proyecto.

---

### 5. Control de estados del viaje

El sistema controla múltiples estados del trayecto:

* SEARCHING
* ASSIGNED
* IN_PROGRESS
* COMPLETED
* CANCELLED

Esto facilita:

* monitoreo del flujo del viaje
* control operacional
* trazabilidad del servicio

---

### 6. Integridad y validación de datos

La base de datos implementa buenas prácticas mediante:

* llaves primarias
* llaves foráneas
* restricciones CHECK
* validaciones automáticas
* índices de optimización

Esto garantiza:

* consistencia de datos
* reducción de errores
* mejor rendimiento de consultas

---

### 7. Escalabilidad del sistema

El modelo fue diseñado para permitir futuras ampliaciones como:

* sistema de pagos
* calificaciones
* notificaciones
* geolocalización avanzada
* historial de estados
* analítica de viajes

Por ello, la arquitectura actual funciona como una base sólida para el crecimiento progresivo del proyecto.
